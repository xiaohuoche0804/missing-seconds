# 第5章 姜远的U盘

苏晚第二天请了半天假。

她用公司的企业信息查询账号查了一下姜远的身份证号。身份证归属地是湖北省某县，1989年生人，今年应该三十五岁。身份证照片是一个长相普通的男人，戴着黑框眼镜，额角有一点疤。

她把这个照片存了下来，然后在公开的社交平台上搜索这个身份证号和姓名。

没有结果。

她又用姜远的手机号去各个社交平台试了一遍。微信、QQ、微博、抖音——全部显示用户不存在。

一个人从社会上消失，先从网络开始。

姜远的痕迹正在以肉眼可见的速度被抹去。

苏晚想起姜远在平台上的账号数据。订单记录、起终点坐标、支付流水——这些数据还保留在公司的服务器里，但用户画像已经全被清空了。一个真实存在过的人，在平台系统里只剩下冰冷的经纬度。

她打开后台系统，试图查一下姜远是否还有其他关联账号。一个手机号通常会注册多个平台，或者换设备登录的时候会有多个设备ID记录。

她在关联分析里输入了姜远的设备ID：xiaomi_13_8T5K92。

结果返回了一条关联记录。

另一台设备，型号是iPhone 14 Pro，设备ID是apple_A2836_IW9K11。这台设备的登录记录显示，它在去年九月中旬到十月中旬之间和姜远的小米手机有过一次关联操作——支付方式绑定。

苏晚查了一下这台iPhone的归属信息。结果让她愣了一下。

iPhone 14 Pro的持有者实名认证信息显示：姜棠。

不是姜远。姜棠。

她搜索了一下这个名字，发现这是一个女性姓名，年龄四十岁左右。身份证归属地是武汉本地。

她又在平台里搜了一下姜棠的账号。结果返回了一笔订单记录：今年三月八日，从汉口区某小区到光谷软件园。

姜棠在姜远消失之后还在正常使用平台。姜棠不是姜远本人，而可能是姜远的亲属。

苏晚把姜棠的账号ID记了下来，然后在地图上标注了她的家庭住址：汉口区某老旧小区。

她做了一个决定：去找姜棠。

光谷到汉口，地铁转公交，将近两个小时。苏晚下午两点出发，四点到达那个小区。

小区门口有一家便利店，她买了两袋水果，然后走进单元楼。

姜棠住在六楼，没有电梯的老公房。苏晚爬上楼梯，在门前站定，敲了三下。

开门的是一个中年女人。短发，微胖，穿着一件旧棉袄，眼睛下面有很重的黑眼圈。

“你是？”

“姜棠姐？”苏晚拿出手机，打开姜远的身份证照片，“我是苏晚。我在查一些事情，想跟您了解一下。”

姜棠的脸色变了。

她没有说话，侧身让苏晚进了门。

屋子很小，客厅堆满了杂物，一张旧沙发上堆着几件没叠的衣服。姜棠把苏晚带进卧室，关上门，靠在墙上看着苏晚。

“你查到什么了？”

苏晚没有绕弯子：“您弟弟姜远的账号在平台上被标记成了无效用户。他最后一次订单是去年9月30日，之后就再也没有任何记录了。”

姜棠的眼眶红了。

她没有哭，只是站在那里，肩膀微微发抖。

“他在10月3号给我打过电话。”姜棠“他说了一件不该发现的事。我问他什么事，他不肯说。他只说让我帮他保管一样东西，然后就把电话挂了。”

“什么东西？”

姜棠转身走到墙角，从一个旧柜子里翻出一个铁盒子。她打开铁盒子，从里面拿出一个U盘，递给苏晚。

“就是这个。”

苏晚接过U盘。这是一枚普通的银色U盘，容量不详，没有任何品牌标识。

“他说过这个东西是什么吗？”

“没有。”姜棠摇头，“他只说，如果他出了什么事，就让我把这个东西交给能用得上的人。我问过他是什么意思，他没回答我。”

苏晚把U盘攥在手里，金属外壳冰凉。

“姜远现在在哪里？”

姜棠沉默了很久。

“半年前失踪的。”她说，“我去报过警，警察说成年人失踪超过四十八小时才能立案。我等到第三天去报案，他们录了口供，然后就没有然后了。”

她的声音变得很轻，像是在说一件已经接受了很久的事情。

“警察说会调监控。但那个科技园附近的监控据说有一段时间是坏的，修复之后发现姜远最后出现的画面在地下停车场，之后就没有了。”

苏晚听到“地下停车场”四个字，心里咯噔了一下。

她问：“姜远在失踪前一周，有没有再去过科技园？”

姜棠想了想，说：“他失踪前那周每天都去。他跟我说他在帮一个朋友查一些东西，很重要。但他没有告诉我是查什么。”

苏晚把U盘收进口袋，站起身。

“姜棠姐，这个U盘我能借走吗？”

姜棠看着她，犹豫了一下，然后点了点头。

“拿走。我留着也没有用。”

苏晚从姜棠家出来的时候，天已经黑了。她在小区门口的便利店买了一罐咖啡，然后找了一家附近的网吧，开了台机器。

她把U盘插进电脑。

U盘里只有一个文件夹，名字叫“logs”。文件夹里有三个文件，都是txt格式。创建时间都是去年九月三十日。

第一个文件叫“nightwatch_2024-09-30.log”。

苏晚点开这个文件。

屏幕上跳出一行行代码。

```
[2024-09-30 14:23:01] nightwatch_svc API called
Endpoint: /v2/track
Request: {"target_id":"P_5591044728","location_history_depth":"full","scope":"realtime"}
Response: {"status":"success","location":"30.5782,114.2917","accuracy":"15m","timestamp":"2024-09-30T14:23:01Z"}
```

苏晚盯着“nightwatch_svc”这个词看了很久。

她把剩下的两个日志文件也打开看了一遍。内容结构类似，都是API调用记录，但请求参数和返回数据略有不同。

她把这些日志内容全部复制下来，存进一个加密文档。

然后她打开浏览器，在公司内网的搜索引擎里输入了“nightwatch_svc”。

结果返回：未找到相关结果。

她又在外网的搜索引擎里输入了同样的关键词。

外网返回了一些无关的结果，都是英文网站，涉及某个游戏平台和一款安全软件。

她在外网的搜索结果里翻了几页，没有找到任何与“nightwatch_svc API”或“nightwatch service”相关的内容。

苏晚把视线从屏幕移开，看着网吧天花板上的日光灯管。

姜远失踪前一周每天都去科技园。姜远发现了一件不该发现的事。姜远在失踪前给姜棠寄回了U盘。U盘里有一份nightwatch_svc的日志文件。

她把姜远最后那笔订单的坐标和日志里的坐标做了对比。

姜远最后一笔订单的终点是30.5782, 114.2917。日志里显示的nightwatch_svc追踪坐标也是30.5782, 114.2917。

完全一致。

姜远在被平台算法过滤之前，就已经知道自己的行踪被追踪了。

他查过nightwatch_svc这个服务。他调用过它的API，查到了自己的实时坐标。

然后他就失踪了。

苏晚把U盘拔下来，放进口袋。

她走出网吧，站在街边，夜风吹得她有点冷。

姜棠说姜远失踪前一周告诉她“发现了一件不该发现的事”。然后他就把U盘寄回了家。

他在发现自己被追踪之后，做了两件事：第一，查到了追踪他的服务叫什么名字；第二，把证据保存下来，寄给了他最信任的人。

然后他就消失了。

苏晚打开手机备忘录，把今天查到的东西加进去：

一、姜远有一个姐姐叫姜棠，住在汉口。二、姜远失踪前一周每天去科技园，声称在帮朋友查东西。三、姜远寄回家的U盘里有nightwatch_svc的日志文件。四、nightwatch_svc这个服务在公司的内网里搜索不到任何信息。五、姜远最后的行踪坐标指向科技园地下停车场。

她看着这几条信息，把手机屏幕关掉。

姜远发现了一件不该发现的事。那件事和nightwatch_svc有关，和科技园的那个无名院子有关。

她不知道姜远发现的是什么事。

但她知道，nightwatch_svc不是一个普通的内部服务。它的名字不在内网搜索结果里，它有独立的API，有实时追踪功能，有“location_history_depth=full”这种不在任何公开文档里的参数。

它是一个被隐藏起来的服务。

而且它在追踪真实的人。

苏晚在路边站了很久，直到一辆出租车停在她面前。

“上车吗？”司机探出头问。

“上。”苏晚拉开车门，坐进后座，“去光谷。”

司机从后视镜里看了她一眼：“这么晚了去光谷？那边很多公司都下班了。”

“我去办点事。”

车子启动，苏晚看着窗外的夜景，脑子里是那个没有名字的院子坐标。

30.5782, 114.2917。

科技园地下停车场。

姜远最后出现的地方。

也是nightwatch_svc追踪姜远时显示的坐标。

同一串数字，指向同一个地点。

苏晚把那个坐标在心里念了一遍，然后闭上眼睛。

她知道自己迟早要去那个地方。

但不是今晚。
